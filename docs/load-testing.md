# 本地压测与报告

AstroMan 内置轻量压测引擎，面向「日常容量摸底 + 回归验证」，不要求理解 JMeter 的线程组与配置元件。

## 新建压测

侧边栏「压测」→「新建压测」，按分组填写：

1. **选择目标**：项目、环境、接口；也可从请求编辑器直接带入配置
2. **线程组**：并发数、持续时间
3. **流量与节奏**：固定并发 / 阶梯加压、Ramp-Up 预热、思考时间、目标 QPS、连接 / 请求超时、跟随重定向、忽略证书
4. **明细记录**：自动 / 完整 / 1% 采样 / 关闭，默认自动
5. **自动停止**：错误率或响应时间达到阈值时停止
6. **SLA 验收**：P95、P99、错误率、最小 QPS

配置可保存为「压测计划」。计划集中在 `/plans` 管理：跨项目列表、配置快照 v2、最近报告与 QPS / P95 趋势、运行 / 新窗口运行、复制、导入导出（默认剔除敏感信息）与删除保护；内置基线、阶梯与长稳模板。

同一进程可并行多个压测任务：同时运行任务数在设置页调整（`stress_max_jobs`，0 = 不限），跨任务并发之和受本机并发预算约束（默认 `auto` 按 CPU / 内存 / 文件句柄与能力检测结果估算，也可切手动指定），任务按 `jobId` 独立停止；关闭压测窗口不会中断任务，重新打开可恢复进度。并行压测同一目标默认拒绝，同主机不同路径仅警告；忽略后报告会标注「多任务叠加压测，不可作为单实例容量结论」。

## 在测试场景中做门禁

「测试场景」支持 `kind=stress` 用例：内联压测配置，运行结束由 Rust 统一判定 SLA（P95 / P99 / 错误率 / 最小 QPS），并可指定 `baselineReportId` 做基线回归。任一指标超标即用例失败，原因进入断言、JUnit 与 HTML / JSON 报告，桌面端与 CLI 判定一致。详见 [自动化测试](automated-testing.md)。

## 实时指标与曲线

- 总请求、当前 QPS、平均 QPS（已发请求 ÷ 已运行秒数）、平均延迟、P95 / P99、错误率、当前并发、当前阶段、状态码分布
- QPS、延迟分位、错误率实时曲线，吞吐图副标显示本次采样峰值
- 顶部显示当前生效的明细记录模式；自动降档时会弹提示

### 明细记录模式

| 模式 | 行为 | 场景 |
|---|---|---|
| 自动（默认） | 预估 QPS ≥ 2000 转 1% 采样、≥ 5000 关闭明细；实测 QPS 连续超阈值同样降档，只降不升 | 日常使用 |
| 完整 | 每个请求都记录，最多 5 万条 | 问题排查、小流量 |
| 采样 | 每 100 个请求记录 1 条 | 大流量下保留代表性样本 |
| 关闭 | 不记录逐请求明细，也不读取响应体内容 | 冲量跑分 |

无论哪种模式，聚合指标（直方图、状态码、错误类型、每秒采样、错误明细）全部保留。

## 报告

HTML 报告按正式交付物编排：封面（结论徽章 + 关键信息）→ 目录 → 01 执行摘要 → 02 测试环境与配置 → 03 吞吐量与稳定性 → 04 响应时间分析 → 05 错误分析 → 06 容量评估与瓶颈定位 → 07 结论与优化建议 → 附录 A/B/C（口径定义、数据完整性、明细导出），打印时封面单独成页。包含：

- 执行摘要：自动结论（通过 / 有条件通过 / 未通过，按 SLA、错误率、综合得分与告警项判定）、核心指标卡（总请求 / 平均 QPS / 90% 分布 QPS / 单并发 QPS / 成功率 / 平均 RT / P95 / APDEX）、目标与达成率、SLA 验收表、按严重程度排序的关键发现（饱和拐点、错误窗口、尾部延迟放大、响应时间漂移、施压端瓶颈等，每条附数据依据）
- 趋势图：完整坐标轴（时间轴 + 数值刻度）、目标 QPS 与 SLA 阈值参考线、升压期高亮、面积填充；响应时间累积分布（CDF，由直方图还原并标注 P50 / P95 / P99）
- 自动分析：饱和拐点检测（最大有效容量 = N 并发 / M QPS）、四维体检打分（容量 / 稳定性 / 错误 / 尾部延迟，雷达图 + 分值条）、分阶段扩展效率（吞吐增幅 ÷ 并发增幅）
- 优化建议：按 P0 / P1 / P2 优先级自动生成，每条绑定触发它的数据条件
- 附录：指标口径定义（含与其他工具对比时的口径差异提示）、指标总览、三处口径自洽校验、数据丢弃与降采样说明
- 可编辑的测试场景与报告总结、施压端信息（核数 / 内存 / 压测期 CPU 峰值）
- 逐请求明细（发起时间、方法、URL、请求体、状态码、耗时、TTFB、响应大小、错误信息，最多 5 万条）

### QPS 指标口径

报告详情页、HTML 报告与 Excel 报告用同一套口径（一个计算入口，三处只做展示），RPS 与 QPS 同义，界面与文档统一写 QPS：

| 指标 | 口径 | 用在哪 |
|---|---|---|
| 平均 QPS | 总请求数 ÷ 实际施压时长（后端聚合），**不是**每秒采样的算术平均 | 结论、SLA 判定与对外汇报的主数字 |
| 峰值 QPS | 所有采样点中的最大值 | 只看瞬时爆发力，不要写进容量结论 |
| 最低 QPS | 稳态窗口内的最小采样值（与 90% 分布同一窗口，剔除升压段与末点） | 观察抖动下限，解释「掉底」现象 |
| 90% 分布 QPS | 每秒采样 QPS 的 P10，剔除升压段与首末不完整秒；含义是「90% 的时间吞吐不低于该值」 | 验收与多份报告横向对比优先用它 |
| 单并发 QPS | 平均 QPS ÷ 并发数 | 判断继续加并发是否只在排队：该值明显下滑说明吞吐已到瓶颈 |
| 目标 QPS / 达成率 | 平均 QPS ÷ 限速目标，与 SLA「最小 QPS」同一口径 | 限速场景确认是否打满、是否超出目标 |
| 稳态 QPS | 阶段内剔除前 20%（升压）与后 10%（切换抖动）后的采样中位数 | 阶梯加压时判断拐点与扩展效率 |

90% 分布 QPS 与平均 QPS 可能差很多，这是正常的：P10 取的是「最差的那 10% 时间」的上界，长尾抖动会被放大。写结论时建议同时给出平均、90% 分布与峰值三个值，避免只报峰值被误读成「可持续承载」。

> 为避免文件体积随时长膨胀，HTML 报告不再内嵌逐条明细表；明细仍在库中，按需单独导出。

导出格式：

| 格式 | 用途 |
|---|---|
| JSON | 完整归档，含全部请求明细 |
| HTML | 自包含可视化报告，不含逐条明细，8 小时压测也在 1MB 量级 |
| Excel | 概览 / 优化建议 / 延迟分位 / 采样 / 请求明细 / 分布 / 状态码 / 错误 / 阶段 / 配置多工作表 |
| 请求明细 CSV | 后端流式直写，几十万行也不会占满内存 |
| 错误明细 CSV | 同上，列与 Excel 明细表对齐 |

## 参数池 / Token 池

当同一接口需要多个账号、多个 Token，或登录态会过期时，用「数据池」准备数据，再在压测里绑定：

1. 建池先定列：列名只能是字母 / 数字 / 下划线且以字母或下划线开头（如 `phone`、`password`、`token`），首列必填，最多 24 列；列名会直接当作 `{{变量名}}` 使用。
2. 导入：下载 Excel 模板（首行即列名、整列文本格式），按表头填数据后「导入 Excel」；也可以粘贴 JSON 数组或文本按列写入。缺首列会报错，未知表头会列入 `ignoredColumns`，超过 15 位的数字会给 `numericWarnings`。
3. 绑定：在压测页「参数池 / Token 池」添加绑定，选「全部列（同名注入）」时列名即变量名，请求里直接写 `{{phone}}`、`{{password}}`；也可只取某一列映射到自定义占位符；模式支持每 VU 固定、逐请求轮换、随机。同池多绑定共用同一条目，同池 mode 必须一致。
4. 预览与开跑：点「预览分配」查看覆盖 VU、条目数、样例值与自动注入列；池不存在、列不存在、变量名为空或条目不足会直接拦截。开跑前界面会强制再预览一次。

401 / 403 可勾选「自动换下一条」重试一次；Token 池还可配置 HTTP 刷新（到期前 30 秒预刷新、连续失败退避并标记失效）。敏感池在列表、预览和 AI 返回里始终脱敏，查看明文需二次确认且 30 秒自动隐藏。示例项目内置「07 数据池示例」及两个示例计划，可直接打开预览。

## 分布式压测（二期）

主节点创建配对会话后，每 2 秒经 UDP 17802 向局域网多播与各网卡广播 Beacon（TTL 6 秒，不含令牌），同一网段的从节点可直接发现并点击加入；也保留 6 位配对码（5 分钟有效、单次使用）与手动填写内网 IP + 端口（默认 17801）的兜底方式。加入请求默认进入主节点「待接受」列表，可接受、拒绝或开启自动接受，每 IP 5 秒限流、待接受上限 3 个；连上后 5 轮握手做时钟对齐。

并发按各节点能力分配：默认 `auto` 按本机预算（CPU / 内存 / 句柄）分配，可选 `even` 平均分配或 `custom` 权重 + 每节点 min/max；分配结果与每节点预算在启动前展示，超出预算或下限冲突会直接拒绝启动。启动前主节点逐节点做目标可达性预检，并对池切片校验 VU 区间连续、无空洞、单节点序列化体积 ≤ 64 MB。运行中每秒采样按主节点时间轴合并，QPS 相加、均值按请求数加权、百分位合并直方图桶后重算；节点序列抽稀后写入报告。从节点失联标记 `lost`，其余节点继续跑完，报告标注「结果不完整（N/M 节点）」；暂不做断线重连与失联后的并发重分配。

环境变量经 X25519 + HKDF + AES-GCM 加密下发（`master_wins` 默认，可切换 `local_wins`），系统占位符不再误报缺失；集群页可用「变量体检」查看主节点与各从节点的变量来源、状态与缺失原因。参数池 / Token 池按全局 VU 偏移切片下发，按 VU 粘性取条目，401 / 403 时按条目单飞刷新后重试一次；从节点在完成时回传本节点池计数，报告可按节点汇总 used / requests / refreshed。

池内容在 prepare 时定快照：开跑后改池、改列或刷新都不会影响本次运行，需要换数据必须重新下发配置。单节点切片序列化上限 64 MB，创建会话时会按池条目估算体量，节点表显示「池切片 X / 64 MB」；超限会报 `E_POOL_SLICE_TOO_LARGE` 并指出最大来源池。计划里存在自定义列绑定（`column` 非空，含 `*`）时，主节点会拒绝版本过低、未上报自定义列能力的从节点并列出节点名；缺少加密公钥的旧从节点只能读取本机同名环境，集群页「兼容」列会明确标注。

多机施压不会提高目标侧容量，主要用于确认瓶颈不在施压端、从多个网络位置观测延迟，以及长稳时分摊压力。

## 本机施压能力

设置页可运行回环阶梯探测（16–1024 并发），得到本机极限 QPS、饱和并发、CPU / 内存峰值与检测时间。结果保留最近 10 次，并写入后续压测报告；报告展示「客户端极限 X QPS / 本次平均 Y QPS / 负载占比 Z%」，接近上限时给出「客户端接近能力上限，结论需谨慎」的提示。该值是回环检测结果，不是目标系统容量，实际受网络 RTT 与目标侧影响。

## 边界

- 并发不再写死 5000：默认按本机预算自动分配，设置页可切手动；实际吞吐取决于本机 CPU、内存、网络与目标服务
- 分布式压测二期需同一局域网且允许 UDP 17802；跨网段、断线重连与失联后并发重分配尚未支持
- 并发 > 1000 时请确认端口与文件句柄限制；单机万级 QPS 建议 8 核以上，并关注报告中的施压端 CPU 峰值
- 压测会真实打到目标服务，请先确认环境和配额
- 压测类操作在航仔里不会自动执行，必须由你确认

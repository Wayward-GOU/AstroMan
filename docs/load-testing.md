# 本地压测与报告

AstroMan 内置轻量压测引擎，面向「日常容量摸底 + 回归验证」，不要求理解 JMeter 的线程组与配置元件。

## 新建压测

侧边栏「压测」→「新建压测」，按分组填写：

1. **选择目标**：项目、环境、接口；也可从请求编辑器直接带入配置
2. **线程组**：并发数、持续时间
3. **流量与节奏**：固定并发 / 阶梯加压、Ramp-Up 预热、思考时间、目标 RPS、连接 / 请求超时、跟随重定向、忽略证书
4. **明细记录**：自动 / 完整 / 1% 采样 / 关闭，默认自动
5. **自动停止**：错误率或响应时间达到阈值时停止
6. **SLA 验收**：P95、P99、错误率、最小 RPS

配置可保存为「压测计划」，下次直接载入；计划按项目管理并可删除。

## 在测试场景中做门禁

「测试场景」支持 `kind=stress` 用例：内联压测配置，运行结束由 Rust 统一判定 SLA（P95 / P99 / 错误率 / 最小 RPS），并可指定 `baselineReportId` 做基线回归。任一指标超标即用例失败，原因进入断言、JUnit 与 HTML / JSON 报告，桌面端与 CLI 判定一致。详见 [自动化测试](automated-testing.md)。

## 实时指标与曲线

- 总请求、RPS、平均延迟、P95 / P99、错误率、当前并发、当前阶段、状态码分布
- QPS、延迟分位、错误率实时曲线
- 顶部显示当前生效的明细记录模式；自动降档时会弹提示

### 明细记录模式

| 模式 | 行为 | 场景 |
|---|---|---|
| 自动（默认） | 预估 QPS ≥ 2000 转 1% 采样、≥ 5000 关闭明细；实测 QPS 连续超阈值同样降档，只降不升 | 日常使用 |
| 完整 | 每个请求都记录，最多 5 万条 | 问题排查、小流量 |
| 采样 | 每 100 个请求记录 1 条 | 大流量下保留代表性样本 |
| 关闭 | 不记录逐请求明细，也不读取响应体内容 | 冲量跑分 |

无论哪种模式，聚合指标（直方图、状态码、错误类型、每秒采样、错误明细）全部保留。

## 报告

HTML 报告按正式交付物编排：封面（结论徽章 + 关键信息）→ 目录 → 01 执行摘要 → 02 测试环境与配置 → 03 吞吐量与稳定性 → 04 响应时间分析 → 05 错误分析 → 06 容量评估与瓶颈定位 → 07 结论与优化建议 → 附录 A/B/C（口径定义、数据完整性、明细导出），打印时封面单独成页。包含：

- 执行摘要：自动结论（通过 / 有条件通过 / 未通过，按 SLA、错误率、综合得分与告警项判定）、核心指标卡、SLA 验收表、按严重程度排序的关键发现（饱和拐点、错误窗口、尾部延迟放大、响应时间漂移、施压端瓶颈等，每条附数据依据）
- 趋势图：完整坐标轴（时间轴 + 数值刻度）、目标 RPS 与 SLA 阈值参考线、升压期高亮、面积填充；响应时间累积分布（CDF，由直方图还原并标注 P50 / P95 / P99）
- 自动分析：饱和拐点检测（最大有效容量 = N 并发 / M QPS）、四维体检打分（容量 / 稳定性 / 错误 / 尾部延迟，雷达图 + 分值条）、分阶段扩展效率（吞吐增幅 ÷ 并发增幅）
- 优化建议：按 P0 / P1 / P2 优先级自动生成，每条绑定触发它的数据条件
- 附录：指标口径定义（含与其他工具对比时的口径差异提示）、指标总览、三处口径自洽校验、数据丢弃与降采样说明
- 可编辑的测试场景与报告总结、施压端信息（核数 / 内存 / 压测期 CPU 峰值）
- 逐请求明细（发起时间、方法、URL、请求体、状态码、耗时、TTFB、响应大小、错误信息，最多 5 万条）

> 为避免文件体积随时长膨胀，HTML 报告不再内嵌逐条明细表；明细仍在库中，按需单独导出。

导出格式：

| 格式 | 用途 |
|---|---|
| JSON | 完整归档，含全部请求明细 |
| HTML | 自包含可视化报告，不含逐条明细，8 小时压测也在 1MB 量级 |
| Excel | 概览 / 优化建议 / 延迟分位 / 采样 / 请求明细 / 分布 / 状态码 / 错误 / 阶段 / 配置多工作表 |
| 请求明细 CSV | 后端流式直写，几十万行也不会占满内存 |
| 错误明细 CSV | 同上，列与 Excel 明细表对齐 |

报告列表勾选 2–4 份，对比总请求、成功率、P95 / P99、QPS、APDEX 与并发等关键指标。

## 边界

- 当前是**本机单进程压测**，未提供分布式压测节点；并发上限 5000，实际吞吐取决于本机 CPU、内存、网络与目标服务
- 并发 > 1000 时请确认端口与文件句柄限制；单机万级 QPS 建议 8 核以上，并关注报告中的施压端 CPU 峰值
- 压测会真实打到目标服务，请先确认环境和配额
- 压测类操作在航仔里不会自动执行，必须由你确认

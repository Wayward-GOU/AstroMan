# AstroMan v1.0.8 发布说明

> 发布日期：2026-11-02 · 基线：v1.0.7 · 相对 v1.0.7 改动 144 个文件、约 4.1 万行

## 一句话概括

v1.0.8 把 AstroMan 从「接口调试 + 压测」扩成三块：**接口调试 / 自动化测试 / 开发工具箱**，同时补上可信执行与数据兜底（脚本沙箱、主密钥、备份恢复、二进制响应），压测报告也统一了 QPS 口径。

---

## 一、新增模块：自动化测试

这是本版本最大的一块新能力，从「手工调一个接口」变成「可回归的一套测试」。

| 能力 | 说明 |
|---|---|
| 数据模型 | `test_suites / test_cases / test_datasets / test_runs / test_run_cases / test_run_assertions / test_artifacts` 七张表，v1.0.7 老库自动补列，不动存量数据 |
| 执行引擎 | 顺序执行、用例依赖与跳过、失败策略、重试、并发与数据行参数化、套件级 setup / teardown、运行取消与崩溃恢复 |
| 声明式断言 | 状态码、响应时间、Header、Body、JSONPath、正则；失败即用例失败，并记录可读差异 |
| 数据集 | CSV / JSON（内联或文件），嵌套字段 `{{a.b.c}}` 渲染；运行期变量优先并跨用例传递 |
| Python 用例 | 本地解释器探测、显式授权、`context.json / result.json` 协议、pre / post / main 钩子；输出与日志限长、附件白名单、密钥脱敏、脚本哈希审计 |
| 运行报告 | 每次运行产出 HTML / JSON（schemaVersion 1.0）/ JUnit XML / summary.txt 与日志附件；失败聚焦、状态筛选、按用例搜索；每套件保留 50 份 |
| 压测用例 | 用例内联压测配置，运行结束按 SLA（P95 / P99 / 错误率 / 最小 RPS）逐项判定；支持与基线报告对比（P95/P99 超 1.2 倍、QPS 低于 80%、错误率高于基线 +0.5% 即失败） |
| 套件包 | `*.astromantest.json` 导出 / 导入，携带套件、用例、请求快照与数据集；同名冲突可 skip / overwrite / rename |
| CLI | `astroman-cli`：`test run / test list / test validate / report export / python check / suite import`，支持 `--env-file`、`--tags`、`--fail-fast`、`--timeout`、`--report`、`--out`、`--json`、`--db`，退出码 0/1/2/3/4/5 |
| 航仔接入 | 新增 12 个 `test_*` 工具：套件与用例读写、启动 / 停止运行、查结果、导报告；`test_run_start` 不套 60 秒超时，启动即返回 runId |
| 上手样例 | 内置「示例回归（httpbin）」套件：3 个可直接运行的 HTTP 用例，分别断言查询参数回显、JSON 字段回显与 Bearer 认证 |

另外，「批量运行」页新增**另存为测试套件**：把当前勾选的接口、顺序与数据文件迁成套件草稿，并预检列出会被跳过的 JS 钩子 / 环境脚本。

## 三、增强：可信执行与数据兜底

### 脚本沙箱

- 前置 / 后置 / 环境脚本改在独立 Web Worker 执行，`while(true)` 不再卡死界面
- 超时可配 1–30 秒（默认 5 秒），超时终止 Worker 并把本次写入的变量**回滚**到执行前快照
- 老 WebView 下自动降级为主线程同步执行，行为与旧版一致

### 密钥加密

- 敏感变量与 AI Key 用主密钥 AES-256-GCM 加密入库（`enc:v1:`），AAD 绑定「表名:列名」，密文搬到别的列必然解密失败
- 三种来源：Windows 凭据管理器 / 降级文件 `keys/master.key` / 口令模式（Argon2id 派生，密钥不落盘）
- 敏感项列表只返回掩码与 `hasValue`；保存掩码或空值时沿用旧密文
- 密钥包导出 / 导入（口令加密），换机前先导出

### 备份与恢复

- 每天一份 + 每周一份自动快照；保留日备 7、周备 4、恢复 / 升级前各 10，总量上限 2GB
- 快照用 `VACUUM INTO` 写 `.part` 再改名，失败不留半个文件；写前检查空间 ≥ 库大小 × 1.5
- 恢复不原地替换：写 `restore.pending` → 重启 → 打开连接池前完成替换，并先留 `pre-restore` 快照
- 启动自动 `quick_check`，设置页可手动 `integrity_check`

### 二进制响应

- 文本直接返回（5MB 上限），二进制落盘 `responses/` 返回路径，超 2MB 的文本同时保留截断正文与完整文件
- 图片 / PDF 返回 64KB 预览；判定链：解压 → `Content-Type` / `Content-Disposition` → 魔数嗅探 → UTF-8 校验
- 「另存为」走文件拷贝，导出完整文件；响应文件按 30 天 / 单目录 1GB LRU 清理

### 耗时分解与重定向

- 「计时」页签：DNS / TCP+TLS / 等待首字节 / 正文下载四段瀑布图；复用连接明确标注「没有新建连接，不是连接很快」
- 重定向手工跟随（最多 10 跳），记录每跳状态码与耗时；303 与 301/302 的非 GET 改写为 GET
- 发送中可「停止」，连接 / 等待 / 下载阶段都能中断；重试仅对 408 / 429 / 5xx，退避 200 → 400 → 800ms，尊重 `Retry-After`

### 协议与压缩

- 按请求切换 HTTP/1.1 或 HTTP/2，响应头旁显示实际协商结果；HTTP/2 下自动剔除 8 个逐跳头并说明原因
- 启用 brotli / deflate，显示压缩前后字节数

### 数据库与迁移

- `PRAGMA user_version` 升到 2；库版本高于程序时拒绝启动，不再静默读坏数据
- 迁移从「逐条 `let _ =` 吞错误」改为判存式（`PRAGMA table_info` 先判列），只忽略「列已存在」，整个迁移在一个事务里

## 四、压测与报告：统一 QPS 指标组

- 新增 `qpsOverview()` 作为**唯一口径**：平均 / 峰值 / 最低 / 90% 分布 / 单并发 / 目标 QPS 与达成率，报告详情页与 HTML / Excel 导出共用，不再出现同一个报告三处数字不一致
- 报告详情 KPI 由 8 张扩到 10 张：新增「90% 分布 QPS」（悬停有口径说明）与「单并发 QPS」；标题区显示「目标 QPS · 达成 x%」
- 压测页实时指标新增「平均 QPS」，「当前 RPS」更名「当前 QPS」，吞吐图副标显示本次峰值
- 压测弹窗「选择目标接口」改为一行三列，接口下拉双行展示方法色标 + 名称 / URL，URL 用当前环境变量渲染成完整地址

## 五、界面与导航

## 七、修复的问题

### 严重：主密钥被测试覆盖

| 项 | 内容 |
|---|---|
| 现象 | 部分用户重装或跑过测试后，已保存的接口密钥、AI Key 全部解不开，设置页显示敏感值为空 |
| 根因 | 单元测试通过 `AppState::headless` 用临时库启动，首次启动会生成新主密钥并写入**共享的**钥匙串条目，把真实安装用的那把覆盖掉 |
| 修复 | ① 测试与 CI 构建永不写系统钥匙串（`keyring_allowed`，也可用 `ASTROMAN_DISABLE_KEYRING=1` 强制走文件密钥）；② 钥匙串条目改为 `AstroMan/master-key/<数据目录指纹>`，多份安装 / 开发实例 / 测试库互不覆盖；③ 旧共享条目首次启动自动迁移，已有数据不受影响 |

### 其他修复

| 现象 | 根因 / 修复 |
|---|---|
| 主密钥对不上时，解不开的值被静默当成空串 | 启动时用 `key_check` 密文 + 密钥指纹 + 抽样解密三重校验；对不上就在设置页提示「主密钥与已保存的密钥值不匹配」并给出受影响条数 |
| 密钥丢失后「导入密钥包」整体报错（而这正是恢复手段） | 允许在密钥不匹配状态下导入，不再因「用错钥匙重加密」失败 |
| 改一个普通环境变量，整个环境的密钥被清空 | 提交值是掩码或空值时沿用旧密文 |
| `v1:` 旧格式迁移时解不开的条目被静默跳过 | 日志指出服务商编号并提示重新填写 |
| 日志里可能出现明文密钥 | 本次运行解密过的敏感值登记后统一替换为 `••••` |
| 死循环脚本卡死整个界面 | Web Worker + 超时终止 + 变量回滚 |
| 数据库迁移吞掉所有错误，坏了也照常启动 | 判存式迁移 + 事务 + 核心表存在性校验，缺失报 `E_CORRUPT` |
| 大响应把二进制当文本渲染成乱码 / 卡顿 | 按形态分流：文本截断 + 二进制落盘 + 魔数嗅探 |
| 请求发了就停不下来 | 取消标志 50ms 轮询，各阶段可中断，取消结果标记 `cancelled` |
| 压测报告里的「被测目标」显示 `{{base_url}}/xxx` 模板原文 | 记录渲染后的实际地址；老报告用运行明细第一条 URL 兜底还原 |
| 同一个报告里「平均 QPS」三处数字不一致 | 统一走 `qpsOverview()` |
| 「最低 QPS」被升压首秒拉低成几十 req/s | 与 90% 分布共用稳态窗口，剔除升压段与末点 |
| 航仔执行测试类写操作时，确认卡只显示「该操作会修改本机数据」 | 9 类测试写操作各写专门说明，并新增计划预览（预检结论、用例数、环境、删除影响等） |
| 工具返回的 `status` / `trigger` / 用例类型是英文枚举 | 补中文映射表；`kind` 保留机器值并另给 `kindLabel`，避免回填时被参数校验拦下 |
| 进程监视只显示 Top 12 | 扩为全部进程，可搜索、按 CPU / 内存排序、结束进程（拦截系统关键进程） |

## 八、升级与兼容性

- **数据**：`user_version` 升到 2，迁移前自动留 `pre-migrate` 快照；迁移失败可从设置页回退。老库升级不丢值
- **密钥**：v1.0.7 的 `v1:` 静态混淆格式可读，启动时自动迁移为 `enc:v1:`。换机或重装前请先在设置页导出密钥包，否则已加密的值在新机器上解不开
- **钥匙串**：首次启动会把旧的共享条目迁移到按数据目录派生的新条目；如果系统里还有旧版本的共享条目，迁移后可以手动清理
- **Python 用例**：需要在「设置 → 网络与安全」打开 Python 脚本开关并指定解释器；预检、CLI 与执行器的未授权提示都会指向该开关
- **CLI**：随安装包与便携包携带 `astroman-cli`（`bundle.externalBin`），release 与 CI 自动按 target triple 编译
- **系统要求**：Windows 10 1809+ / Windows 11（ARM64 可直接运行 x64 包）；macOS 10.15+。Windows 7 / 8 / 8.1 与 macOS 10.14 及更早系统无法运行
- **签名**：安装包已做 ad-hoc 签名但未做 Apple 公证，SmartScreen / Gatekeeper 首次提示属正常现象

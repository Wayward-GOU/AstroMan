# AstroMan v1.1.3 发布说明

> 发布日期：2026-11-22　｜　数据库：v21　｜　集群协议：v2（增量兼容，未变更）
>
> 完整变更见 [CHANGELOG](../CHANGELOG.md)，代价与取舍见 [分布式压测优化清单](cluster-optimization-plan.md)。

## 版本亮点

v1.1.3 的主线是 **把分布式压测的成本从主节点身上摘下来**，并把「配过谁、跑过什么、机器扛不扛得住」留下来：

- 主节点自己也在施压，本版先修掉和引擎抢资源的几处热点：采样无上限、每秒一次落库、逐条 IPC。
- 从机不再只报 QPS：整机 CPU、内存、线程、网卡收发随采样上行，节点表和报告都能看到「谁先到瓶颈」。
- 主从两侧都能查历史：主节点看任务配了哪些机器、每个节点干了多少活；从节点看本机参与过哪些任务。
- 折线图不再每秒重算：默认 2 秒一帧，最小化到托盘时彻底停止渲染。

## 新增与升级

### 分布式压测优化

- 采样裁剪：`node.samples` 改环形缓冲，只保留最近 300 条，30 分钟 × 16 节点不再累积十几 MB 直方图。
- 落库节流：节点采样 5 秒批量落库，压测期间不再和报告写入抢 SQLite 写锁。
- 心跳回写：`EngineStats` 回写 CPU / 内存 / 整机指标，运行期节点表不再显示 `—`。
- 通道背压：从节点采样走有界队列 1024，拥塞时主动丢采样并累计 `droppedSamples`，不让 WS 发送拖住压测引擎。
- 配对码限速：同 IP 10 秒 5 次失败即拒绝，累计 10 次自动换码。
- 时钟漂移：施压期每 60 秒复测一次，只记漂移不改偏移；超过 50ms 在节点表与报告标注。
- 拆分 `server.rs`（4219 行）为 `mod / persist / pairing / tests`，后续改动不再挤在一个文件里。

### 从机资源指标

- 新增 `HostSample`：整机 CPU、整机内存、进程线程数、网卡收/发速率、1 分钟负载；主节点自身走同一采集器。
- 节点表新增「整机 CPU」与「时钟漂移」，进程 CPU 和整机 CPU 分开看。
- 报告：样本表补 5 列，节点表新增「资源峰值」，集群曲线可切 QPS / 并发 / P95 / 整机 CPU / 进程内存 / 网络。
- 旧报告缺资源样本时新增指标置灰，不画成 0；旧从节点显示 `—` 并在报告注明。

### 配对历史与执行历史

- 主节点「历史」tab：状态筛选、关键字、分页；详情抽屉展示节点地址、并发、QPS、资源峰值、时钟偏差、采集健康度，可跳报告。
- 从节点「本机参与过的任务」：加入方式、并发、峰值 QPS、本机资源峰值、结束状态，可清空。
- 新增 IPC：`cluster_jobs_list / cluster_job_detail / cluster_jobs_clear / cluster_slave_history_list / cluster_slave_history_clear`。
- 清理只针对已结束任务，运行中任务不受影响；主从历史互不同步，从机不落主节点报告。

### 渲染节流

- 后端按秒聚合 `cluster:sample-frame`，IPC 从「节点数 × 每秒」降到每秒 1 帧；原始直方图只留在后端。
- 前端非响应式缓冲 + 节拍提交：实时 1 秒 / 平衡 2 秒（默认）/ 省资源 5 秒，存 localStorage。
- 页面隐藏时停止渲染只保留缓冲，回前台一次补齐；超过 60 点按步长抽稀，图表用 `shallowRef`。
- 缺失秒补 `null` 断线，不再按下标等距压缩时间轴。

### 航仔与体验

- 压测配置新增「本次变量」自查：按普通 / 密钥 / 系统分类展示来源与缺失原因，不返回值。
- 修复 `{{os:NAME}}` 被环境变量或数据池同名变量顶掉的问题。
- 航仔新增 4 个只读工具：`cluster_jobs_list`、`cluster_job_detail`、`cluster_slave_history`、`stress_var_sources`。
- 样式门禁口径修正（排除实体误判与已令牌化声明），基线按真实值收紧并清理兜底色值。

## 升级与兼容

- 数据库 v20 → v21：新增 `cluster_slave_history` 表，`cluster_report_samples` 补资源列；只补表补列，老数据保留，重复启动不会因 `ALTER TABLE` 报错。
- 主从协议保持 v2：新字段全部可选，新旧节点可混合组网，只是资源列显示 `—`。
- 旧报告、旧计划、旧数据池无需迁移；未使用分布式压测的用户不受影响。

## 已知限制

- 从节点断线不自动重连，跨网段仍需手动 IP；故障后的并发不重分配（三期）。
- 主节点合并仍为结束时全量遍历，16 节点 × 30 分钟以内可接受。
- 整机指标依赖 `sysinfo`，Windows 的 `load1` 恒为 0；网络速率按真实采样间隔差分，间隔抖动时会有小幅毛刺。

## 验证基线

- `cargo check --all-targets`、`cargo test --lib`（串行）通过；`cluster::` 51 项通过。
- `npx vue-tsc --noEmit`、`npx vitest run` 通过。
- 合并吞吐用例 `cluster::acceptance::two_node_smoke` 单独跑通过；并行跑时受机器负载影响会出现 3% 阈值抖动，属既有波动用例。

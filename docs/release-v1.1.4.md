# AstroMan v1.1.4 发布说明

> 发布日期：2026-11-23　｜　数据库：v23　｜　集群协议：v2（增量兼容，未变更）
>
> 完整变更见 [CHANGELOG](../CHANGELOG.md)。

## 版本亮点

v1.1.4 的主线是 **把压测报告从「分析结论」改成「可核对的事实」**，同时补齐图表与导出：

- 报告不再输出关键发现、优化建议、评分与推断性容量结论，只展示采样和聚合得到的事实数据。
- 新增 URL 聚合、错误地址、施压机明细，报告能回答「哪些地址慢、哪台机器先到瓶颈」。
- 页面支持按具体时间段查看成功 QPS、失败 QPS、并发与平均响应时间；时间轴统一为完整日期时间。
- 页面与 HTML / Excel 导出的图表、指标配色与免责声明保持同一口径。
- 依赖安全升级：`cargo audit` 漏洞从 11 条降到 0。

## 新增与升级

### 报告重构

- 章节调整为结果汇总、配置、吞吐与并发、响应时间、错误与状态码、URL 与施压机、附录。
- URL 统计按「方法 + 地址 + 状态码」聚合请求数、成功 / 失败、总耗时、最长耗时及时间、流量与首条错误样例；与 `recordDetail` 是否记录明细无关。
- URL 查询参数与错误信息中的 token / password / secret / authorization / cookie / Bearer / sk- 等统一脱敏。
- 施压机明细：单机 1 行、集群按节点展开，包含总 / 成功 / 失败、平均耗时、TPS、出站带宽；失联节点缺失字段显示「—」。
- 报告支持编辑标题；「再次运行」优先复用关联计划，计划或请求不存在时回退配置快照。
- 页面、HTML、Excel 统一免责声明。

### 图表与导出

- 修复响应时间累积分布在开放区间（>60s）与零计数桶下横轴被压成 0~1 的空图问题。
- 新增 QPS、并发请求数、平均响应时间、成功 / 失败 QPS、QPS-延迟散点、接收带宽、TTFB / Body 趋势。
- 新增请求结果、状态码、错误类型、流量构成环形图；HTML 中四张环形图一行紧凑展示。
- 多 URL / 多施压机 / 多阶段时输出平均响应、TPS、阶段 QPS 与 P95 对比条形图。
- 页面新增时间范围筛选（时间选择器 + 双滑块），「分时段趋势」按所选时间段展示成功 QPS、失败 QPS、并发请求数与平均响应时间。
- 页面与 HTML 导出时间轴统一为 `YYYY-MM-DD HH:mm:ss` 并旋转标签；导出中的成功 / 失败 QPS 拆成两张独立趋势图。
- 核心指标按语义分色：吞吐主色、峰值蓝、90% 分布绿、单并发紫、延迟警示色，成功率与 APDEX 按结果取色。
- Excel 新增「说明 / URL 统计 / 错误地址 / 施压机详情」工作表，说明页包含口径、完整性、脱敏与免责声明。

### AI 与数据

- 报告解读提示词与 `report_get` 工具接入 URL 统计、错误地址、施压机明细、TTFB / Body / 带宽与数据完整性。
- 缺失字段明确标注「未记录」，不补 0、不猜测。

### 依赖安全

- `calamine` 0.26 → 0.38、`rust_xlsxwriter` 0.77 → 0.103：移除带 11 条安全公告的 `zip 2.1.6` 与 `quick-xml 0.31`，Excel 模板 / 导入导出行为不变。
- `url`、`rustix`、`async-executor` 补丁升级；`cargo audit` 漏洞数 11 → 0。

## 升级与兼容

- 数据库升级到 v23：新增 `report_url_stats` 表与索引，`test_reports` 新增 `report_title`；只补表补列，旧报告保持可读。
- 主从协议保持 v2：`DonePayload` 增加可选 `url_stats` / `url_stats_complete`，旧从节点照常加入；URL 统计缺失自动标记不完整，不阻塞任务。
- 旧报告、旧计划、旧数据池无需迁移；未使用压测报告的用户不受影响。

## 已知限制

- 报告只展示事实数据，不提供容量结论或优化建议。
- 旧报告缺少 URL 统计、TTFB / Body 等字段时显示「未记录」或「—」，不做推断。
- 集群报告中断联节点或旧节点的 URL 统计会标记为不完整。

## 验证基线

- `cargo test --lib`、`cargo clippy --all-targets` 通过。
- `vue-tsc --noEmit`、`vitest run`（349 项）、`npm run build` 通过。

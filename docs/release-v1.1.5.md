# AstroMan v1.1.5 发布说明

> 发布日期：2026-11-24　｜　数据库：v23（未变更）　｜　集群协议：v2（仅新增可选字段，旧节点照常参与）
>
> 完整变更见 [CHANGELOG](../CHANGELOG.md)。

## 版本亮点

v1.1.5 的主线是**把高频页面做顺手，把大体积数据做稳**：

- 请求页交互重做：顶栏文字按钮收成图标组，新增「实际请求」页签，状态栏按「状态 · 耗时 · 大小 · 协议」重排。
- 大响应不再卡死界面：超过 1MB 分块续渲，超过 128KB 关着色、超过 1MB 关搜索，并说明降级原因。
- 请求体 / 上传文件有了明确上限（32MB / 2GB），超限直接拒发并给出替代做法，不再把进程顶爆。
- 工具箱 8 个双栏工具与请求区统一切换左右 / 上下分栏，分隔条可拖动、比例按方向分别记忆。
- 分布式压测节点区改为「一台机器一张卡片」，配置、实时资源与本次配对以来的峰值一眼看完。

## 新增与升级

### 请求页交互

- 顶栏由 12 个文字按钮收为图标组：历史、文档、代码、Cookie、AI 发送选项、证书、删除；证书关闭时用危险色底提示。
- URL 条去掉多余竖分隔线，发送按钮定宽，协议下拉保证 `HTTP/1.1` 不被截断。
- 新增「实际请求」页签：展示最终 URL、带来源标记（用户 / 认证 / 自动）的请求头、未解析变量的橙色告警，并支持筛选与复制；底部注明 Host / UA / Accept-Encoding 由底层 HTTP 客户端补齐，前端拿不到。
- Headers 页签加筛选框、`n/总数` 计数与一键复制全部。
- 响应状态栏改为分组展示，同时保留停止 / 重试 / 跳转 / 断言入口。
- 页签改为细线风格并隐藏无意义徽标（认证「无」、Body「none」、计数 0），6 个页签在 1440px 下不再折叠。

### 大响应体与体积上限

- 响应正文超过 1MB 时改为分块渲染（首屏 96KB、后续每块 192KB，切点落在换行之后），已渲染的块不再重新排版。
- 语法着色阈值单独设为 128KB、搜索阈值 1MB：实测 128KB 着色约 0.13s、512KB 约 1.7s、1MB 约 6.7s，大响应打开即卡死的问题由此消失。
- 请求体上限 32MB（前端在触发前置脚本之前拦截，后端兜住批量 / 套件 / AI / CLI 等其它入口）；单个上传文件上限 2GB，先读元数据再决定是否读入内存。
- multipart 的本地文件与 Binary 正文不计入 32MB 请求体上限，避免「选一个视频就被拒」。

### 分栏拖拽

- 请求区与工具箱统一用 `SplitPane`：支持左右与上下两种方向，分隔条可拖动、双击复位，方向可一键切换。
- 比例按方向分键保存（`xxx:ratio:vertical` / `xxx:ratio:horizontal`），切换方向不会互相污染；默认上下分栏。
- 高度按窗口自适应：左右 `clamp(560px, 76vh, 1080px)`、上下 `clamp(620px, 82vh, 1200px)`，窗口窄于 1200px 时换用更紧凑的一档。
- 接入范围：JSON 工作台、代码格式化、AES、Markdown、Diff、正则、MyBatis、图片 Base64 共 8 个双栏工具，以及请求编辑器；原来写死的 `min-height` / `max-height` 一并清除，避免拖动后溢出。

### 分布式压测：节点机器卡片

- 节点区默认「机器卡片」视图，面板头可切回 13 列表格，选择写入 `localStorage`。
- 卡片信息自上而下：主机名 / 地址 / 角色 / 状态 → CPU 核数 / 内存 / 预算并发 → 整机 CPU 与内存仪表条（70% 转警示色、85% 转危险色）→ 分配并发 / QPS / 时钟偏移 → 峰值行 → 徽标行（并发范围、网络、线程、负载、采集健康、新旧版本）。
- 卡片顶部 2px 色条按角色与状态双重编码（主节点铜色、正常绿、告警橙、异常红），左侧保留文字徽标，不依赖颜色也能分辨。
- 底部一行灰度小字汇总**本次配对以来**的峰值：`峰值 QPS 1,800 · 并发 200 · CPU 86% · 内存 52% · 网卡 6.5 MB/s`；实时值留在仪表条与指标格里，峰值只在峰值行。hover 显示「峰值 vs 当前」逐项对照，未跑过的维度自动省略，节点重新配对时归零。
- 峰值由主节点在心跳里累计（只升不降，`NaN` / `inf` 直接丢弃），前端只负责展示。

### 施压端并发预算

- 启动时自动把 `RLIMIT_NOFILE` 软上限抬到系统硬上限（上限 10 万，只升不降，GUI 与 CLI 两条入口都执行）；此前全仓没有 `setrlimit` 调用，macOS 从 Finder / launchd 启动若继承到 256 的软上限，整机并发预算会被压到 153 且只说「受 fd 限制」。提升失败或硬上限本身较低时记一条 warn，写明被压到多少并发。
- 句柄折算系数 0.8 → 0.6，给 SQLite、日志、WebView 与抓包留出余量。
- 预算推导抽成纯函数 `auto_budget()`：`min(max(核数×512, 能力探测, 1000), min(句柄×0.6, 内存GB×256, 10 万))`；设置页「受限项」改为中文口径，受句柄限制时给出 `ulimit -n 65535` 的可操作提示。

## 修复

- 修复编辑窗口缩放到 50% 后无法恢复的问题：移除滚轮缩放（macOS 触控板捏合会带 `ctrlKey`，一路打到下限并持久化），加一次性迁移把历史误调值清回 100%，折叠态保留百分比徽标、点击复位。
- 修复工作台在接口 / 报告 / 项目数据为空时白屏的问题（三处空指针兜底）。
- 修复折叠侧边栏后底部、卡片与版本号样式丢失的问题。

## 升级说明

- 直接覆盖安装即可，数据库结构未变（v23），无需迁移。
- 主从协议仍是 v2，新增的节点峰值字段为可选：旧版从节点照常参与，只是卡片上的资源峰值显示为空。
- 分布式压测手动指定大并发时请配合 Ramp-Up：一次性拉起上千 VU 会撞 accept 队列，表现为 QPS 断崖下跌。

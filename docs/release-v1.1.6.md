> 发布日期：2026-11-27（覆盖重发）　｜　数据库：v23（仅增量加列，启动自动迁移）　｜　集群协议：v2（仅新增可选字段，旧节点照常参与）

>
> 本次为同一版本号的覆盖重发：安装包已替换为最新构建，新增多接口合并压测、报告与导出改版、航仔多接口能力。版本号未变，应用内自动更新不会提示，请重新下载安装包覆盖安装；数据库与主从协议均无破坏性变化。

## 版本亮点

v1.1.6 的主线是**把压测中心的「并发上限、指标口径、多机协作」三件事做扎实**：

- 局域网里装了 AstroMan 的机器会自动出现在「在线设备」列表，主节点在配对阶段可以一键邀请，对方在本机点「接受」即加入分布式压测，点「拒绝」则什么都不发生。
- 并发预算改成按 CPU / 内存 / 句柄推导的纯函数并补了单测，macOS 句柄软上限在启动时自动抬到硬上限，Windows 用独立的句柄预算兜底，两平台的预算口径终于对齐。
- 指标口径全面校正：采样改为「区间增量」、阶段汇总用阶段内真实直方图、TTFB 与响应体只统计拿到响应的请求、APDEX 把失败请求算作失望、报告时长不再把等待在途请求的 5 秒算进去。
- 分布式合并补齐 `responseCount` / `sumBodyMs` / Body 稀疏桶 / APDEX 分子，新旧节点混跑时自动回退到直方图估算并在报告里标注。
- 压测支持**一次合并多个接口**，按权重分配流量、共享 Token / 参数池，最终只产出一份含「按接口汇总」的报告；报告导出新增经典版式，图表横轴改为完整时间并自动控制标签密度。

## 新增与升级

### 多接口合并压测

- 压测页可一次选中多个接口（上限 20 个），每个接口保留自己的方法、Headers、Params、Body 与认证配置，共享计划级的 Token 池与参数池绑定；选中顺序的第一个接口作为报告主目标。
- 新增流量权重：按权重占比把请求分发给各接口，留空或全部为 0 时平均分配；未配置 `requests` 的旧计划自动回退单接口逻辑，无需迁移。
- 后端新增 `StressRequestDef` 与 `StressConfig.requests`：prepare 阶段统一归一化权重、预检与收集变量；引擎按累计权重随机选择目标，单接口时仍走原来的直通路径。
- 报告快照写入 `requestCount` 与 `requests`（接口名、方法、解析后地址、模板地址、归一权重）；报告页与经典报告的目标统一显示「全部接口（共 N 个）」。

### 报告与导出改版

- 报告详情新增「按接口汇总」：把 URL 统计按「方法 + 地址」归并出每个接口的请求数、成功 / 失败、成功率、平均响应与最长响应，多接口报告可直接逐接口解读，不再只看整体。
- 导出新增 `classic`（经典 HTML）格式：封面、目录、KPI 卡片与斑马表格重做；趋势图控制点夹紧在绘图区内，避免样条过冲画出边界；横轴改为每秒短刻度 + 完整日期时间标签，标签数量按实际像素宽度自动计算并统一 -60° 左下倾斜。
- 默认 HTML 报告同步改版：封面渐变与 Kicker、KPI 卡片语义色条、目录胶囊、表格斑马纹与悬停高亮，并补齐移动端与打印分页适配。
- 应用内报告页布局优化：补卡片内边距、`overview-main` 改为弹性布局、章节标题加竖条与分隔线、指标卡加大、间距统一。

### 航仔工具升级

- `plan_save` / `stress_start` 新增 `requestIds` 与 `requestWeights`：id 去重、最多 20 个，权重按顺序对应，缺省或 0 交给后端平均分配；保存时只落 id 与权重，执行时再读取请求库中的最新定义。
- `report_get` 对多接口报告额外返回「按接口汇总」，系统提示要求模型优先引用该字段，禁止按 URL 自行猜测各接口表现。
- `report_export` 新增 `format: html | classic`；压测计划与报告解读提示词同步补充多接口说明。

### 局域网设备发现在线 + 邀请加入（17803）

- 每个开启「设备发现」的实例每 3 秒通过 UDP 17803 广播一次在场信息（多播 + 受限广播 + 定向广播），10 秒收不到即从列表移除；保留原有 UDP 17802 主节点发现。
- 「在线设备」展示主机名、地址、系统与架构、核数 / 内存 / 并发预算、忙闲状态、是否可被邀请；本机单独标记，不参与邀请。
- 主节点在配对阶段选中设备即可发起邀请；被邀请方弹出全局窗口，显示主节点名称、地址、任务名与预计并发，「接受」后自动连入并按分配并发参与压测，「拒绝」只回执不产生任何连接。
- 邀请安全边界：只接受私网 / 回环来源；回连地址以 TCP 真实来源 IP 为准（不信任报文里的 host）；邀请令牌 32 字节随机、一次性、绑定主节点任务、120 秒过期；同一 IP 5 分钟最多 3 次；同一设备同一时刻只保留 1 条待处理邀请；只有出现在在线列表里的设备才能送来邀请。
- 设置页新增「设备发现」开关、设备名与邀请策略（询问 / 自动接受 / 关闭），保存后立即生效，无需重启。

### 施压端并发预算与网络栈

- 预算推导抽成纯函数 `auto_budget`：CPU 每核 512、内存每 GB 384、句柄 × 0.75，上限 10 万，下限 1,000；「受限项」在设置页按中文展示（CPU / 句柄 / 内存 / 检测值）。
- 启动时把 `RLIMIT_NOFILE` 软上限抬到 `min(硬上限, 100000)`（只升不降，失败记 warn）；Windows 无 rlimit，按 16,384 句柄预算兜底。
- 压力客户端开启 `tcp_nodelay` 并把每主机空闲连接上限提到 100,000，避免高并发下反复重建连接。
- 限速器改为 100ms 节拍 + 小数令牌累计（`rate=10.5` 不会每次都向下取整），并用 `Notify` 唤醒等待中的 VU，不再秒级轮询。

### 指标采集与统计精度

- 每秒采样改为**区间增量**：QPS 按两次采样之间的真实秒数计算，2s / 5s 降频采样不再把 QPS 放大 2 / 5 倍；趋势图与报告曲线回放一致。
- 阶梯阶段汇总使用阶段内真实直方图与累计耗时：QPS = 阶段请求数 ÷ 阶段实际覆盖秒数，P95 由真实桶重算；阶梯切换时强制补一个采样点，避免整段请求被算到下一个阶段。
- TTFB 与响应体耗时只统计**拿到响应**的请求（新增 `responses` 分母），连接失败与超时不再按 0 计入而拉低均值；响应体耗时在单次请求内单独测量，401/403 重试时不会把第一次请求算进来。
- APDEX 分子只累计成功请求，失败请求自动落入「失望」档；分母为总请求数。
- 标准差改用精确平方和（不再用直方图桶中值），分位数改为桶内中点插值，相邻桶不再跳变。
- 报告时长与 `end_time` 按停止发压的时刻计算，不再把最长 5 秒的 drain 时间算进平均 QPS。
- 状态码计数拆成 8 个分片锁、URL 聚合拆成 16 个分片并加线程内键缓存，高 QPS 下锁争用显著下降；慢请求队列改为有界，报告采样批量写入（500 行多值 INSERT）。

### 分布式合并口径

- 每秒采样新增 `responseCount`、`sumBodyMs` 与响应体稀疏桶；最终结果新增 `responses`、`sumBodyMs`、`metricsVersion` 与 APDEX 分子。
- `metricsVersion >= 2` 且没有失联节点时使用精确 APDEX 与响应数口径；旧节点或失联节点自动回退到延迟桶估算，并在报告「数据完整性」内标注。
- 合并后的逐秒 Body P95 由各节点上报的响应体桶重算，不再恒为 0；TTFB / Body 均值以响应数为分母。
- 报告新增 `report_samples.response_count` 列（启动时自动加列，旧报告该值为 0 时前端回退到成功 + 失败数）。

### 平台适配（macOS / Windows）

- Windows 的 UDP 会把 ICMP port unreachable 报告成下一次 `recv` 的 `ConnectionReset`，原先会直接终止发现线程导致设备发现永久停摆；现在 `ConnectionReset / ConnectionAborted / Interrupted` 只当作瞬时事件跳过。TCP `accept` 在对方提前断开时（Windows 常见 `ConnectionAborted`）也不再写入常驻错误。
- 平台分支复核：`rlimit` / `libc` 全部在 `cfg(unix)` 内，Windows 走句柄预算；打包矩阵覆盖 Windows x64 / x86（NSIS + 离线包 + 便携版）与 macOS universal dmg。

## 安全与依赖

- `cookie` 0.18.2 → 0.18.3，修复 RUSTSEC-2026-0594（`PrivateJar` 在 fork 后可能复用 AES-GCM nonce）。本应用不使用 `PrivateJar` 也不 fork，实际不可达，仍按补丁版本升级。
- `src-tauri/.cargo/audit.toml` 记录唯一一条忽略项 RUSTSEC-2024-0429（glib 0.18 的 unsound）：该依赖只由 Linux 端 webkit2gtk / gtk 传递引入，本项目不发布 Linux 产物，且上游 tauri 2 尚未提供升级路径。
- CI 的 `cargo audit` 现已通过（0 漏洞），此前的失败来自新发布的 cookie 公告，与本版功能改动无关。

## 兼容性说明

- 数据库结构版本仍为 v23：本版只新增 `report_samples.response_count` 一列，由增量迁移自动补齐，无需手动处理；旧报告该列为 0，前端按「成功 + 失败」回退。
- 主从协议仍为 v2：新增字段全部可选，旧从节点可以继续参与，只是 Body P95 / 精确 APDEX 显示为空或回退值。
- 在线设备发现在 Windows 上需要放行入站 `UDP/TCP 17803`；分布式压测仍需 `TCP 17801` 与 `UDP 17802`。

- 直接覆盖安装即可，数据目录与历史报告不受影响。
- 本次为同一版本号的覆盖重发，应用内更新不会提示；请重新下载安装包覆盖安装，历史数据与配置保持不变。

# AstroMan v1.1.7 发布说明

> 发布日期：2026-11-27　｜　数据库：v24（新增接口采样表，启动自动迁移）　｜　集群协议：v2（仅新增可选字段，旧节点照常参与）
>
> 完整变更见 [CHANGELOG](../CHANGELOG.md)。

## 版本亮点

v1.1.7 的主线是**让多接口压测报告能逐接口看吞吐**：

- 多接口报告不再只有「按接口汇总」的累计值，新增按接口的每秒 QPS 曲线，能看到每个接口的抖动、拐点与掉底。
- 单机与分布式同一口径：每个节点内部先把各接口汇总成一个数，节点之间再按同秒相加，和全局 QPS 完全对齐。
- 报告详情页、标准 HTML、Excel 与经典 HTML 四处展示/导出口径一致，不再各自统计。
- 本版同时包含 1.1.6 之后积累的 Token 看板、CC Switch / 抓包观测数据源、上游代理与 PAC 自动捕获等能力，详见下方 CHANGELOG 中 1.1.6 小节。

## 新增与升级

### 按接口 QPS 曲线

- 引擎在每次请求完成时同时累加全局与对应接口的计数器，每秒采样产出各接口的 QPS、成功数、失败数与平均耗时；单接口压测不受影响。
- 分布式从节点把各接口增量随每秒采样上报；主节点按 `(elapsed_sec, interface_index)` 合并，QPS 与计数直接相加，平均耗时按请求数加权。
- 新表 `report_interface_samples` 保存合并后的曲线，`DB_VERSION` 从 23 升到 24；老库启动时自动补表，旧报告打开后接口曲线为空，不影响其他内容。
- 报告详情页新增「接口 QPS」卡片，下拉切换「全部接口（汇总）」或单个接口；配置里的接口名优先展示，缺失时回退 URL。
- 标准 HTML 增加「接口 QPS 趋势」多线图；Excel 增加「接口采样」长表；经典 HTML 增加同口径多线图并自动换行图例。
- 曲线按接口最多保留 2 万点，24 小时长压测也不会让报告表膨胀到不可用。

### 兼容性

- 数据库 v24 只新增表与索引，不清空、不重建历史报告。
- 集群协议仍为 v2，`SamplePayload.interfaces` 为可选字段；旧节点参与时不发送接口增量，报告会把 `interfaceSamplesComplete` 标为 `false`，曲线可能偏低。
- 单接口计划、`recordDetail=off` 的报告同样会生成接口曲线（接口计数不依赖明细记录）。

## 验证基线

- `cargo test --lib`：集群合并、压测引擎与数据库迁移用例全绿，新增「同秒接口 QPS 相加」「旧节点标记不完整」两个合并用例。
- `npm run test`：报告导出与经典 HTML 新增接口曲线用例。
- `npm run version:check`、`npm run build`、`npm run ui:check` 全绿。

## 升级说明

- 直接覆盖安装即可，启动时自动把数据库从 v23 迁到 v24。
- 分布式混跑时建议主从都升级到 1.1.7；只升级主节点也能出报告，但旧节点的接口曲线会缺失并标注。
- 接口曲线按配置 `requests` 顺序取色，接口数量超过 10 个时颜色循环使用。

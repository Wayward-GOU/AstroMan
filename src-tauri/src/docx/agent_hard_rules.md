# 小HI Agent — 代码层硬规则（调度器强制执行，模型绕不开）
> 版本：v1.1（2026-10-28 更新：轮次 8 次、写操作全量确认、重复调用拦截、工具结果入上下文）
> 作用：弥补LLM Prompt软规则的不可靠，防止幻觉乱操作本地数据、网络、压测。

1. **最大轮次保护与收尾**
   单轮用户请求，最多允许连续 8 次工具调用（`MAX_TOOL_ROUNDS`）。
   达到阈值时不直接终止：先置 `forcedFinal`，要求模型「禁止再调用任何工具，立即输出已完成的步骤、已知信息与最终结论」；仍继续调用工具才终止，并返回提示给用户：「已达到最大执行轮次，本次任务终止，请调整你的需求重试」。
   第 7 轮起在回灌内容里提醒「轮次即将用尽，这一轮之后必须直接给结论」。

2. **工具调用数量拦截**
   如果LLM输出同时多个tool_call，调度器直接拒绝执行，把错误信息返回给LLM上下文：`单次仅允许调用一个工具，请重新选择工具与参数`。
   连续 2 次被全部拒绝后终止本轮，提示用户手动点工具卡片运行。

3. **参数强校验**
   所有工具入参执行JSON Schema校验：类型、必填字段、正则、枚举范围。参数非法拒绝调用底层FbinHttp，校验错误作为Observation回传给LLM，让模型修正参数。

4. **写入操作必须先给方案、经用户确认**
   判定统一走 `isWriteTool()`（= 工具自带 `danger: true` ∪ `WRITE_TOOLS` 白名单），覆盖：
   - 新建 / 修改 / 删除：项目、集合、请求、环境变量、脚本、压测计划
   - 发起 / 停止压测，批量执行
   - 导入导出项目 / 报告 / OpenAPI / 历史记录
   - 切换当前环境
   命中的工具**不能由模型直接落库或开跑**，必须：
   - 提示词先要求模型用文字给出完整计划（做什么、影响对象、关键参数、结果与风险），并询问「是否确认执行」；
   - 用户同意后才输出工具块；未确认前只允许调用只读工具（`*_list` / `*_get` / `*_search` / `*_options` / 统计类）；
   - 调度器再弹 `Modal.confirm`，框内用 `previewArgs()` 展示人类可读的计划（压测计划逐项列出模式、并发、时长、阶段、SLA）；
   - 用户确认或拒绝的结果，都作为Observation消息塞进LLM上下文；拒绝后不得自动重试同一写入。
   一次只推进一件事：保存计划后先停下问是否执行，禁止同一轮内「新建 + 启动 + 导出」连跳。

5. **重复调用拦截**
   以「工具名 + 规范化参数」生成指纹（`callKey()`）：
   - 命中缓存时复用上次结果并提醒模型换工具 / 换参数或直接给结论；
   - 连续两次命中即进入 `forcedFinal`，防止原地打转耗尽轮次。

6. **工具结果必须进入对话上下文**
   `ask(extra)` 要把工具结果、纠正指令写入 `messages`（`hidden: true` 只影响显示）并落库。
   否则模型下一轮看不到上轮结果，会反复调用同一工具，表现为「重试到达上限但任务没跑出来」。

7. **超时控制**
   - 普通http调试、工具箱工具：30秒超时
   - 压测类：以用户配置的压测时长作为兜底超时
   超时后标记任务失败，将超时信息回传给Agent上下文。

8. **数据脱敏兜底**
   工具返回结果回传给LLM上下文之前，对密钥、token、appSecret做脱敏处理，禁止明文密钥进入大模型上下文。

9. **原生工具标记兜底**
   模型漏出 `<fbin-tool>` 伪围栏、`<｜DSML｜tool_calls>`、`<{tool_call}>` 等原生语法时：
   - `normalizePseudoFence()` 先还原伪围栏；
   - `liftNativeCalls()` 抽取平衡 JSON 还原成标准 fbin-tool 块，`stripNativeTags()` 清残留；
   - 救不回来则隐藏该条并自动纠正，最多 2 次；空工具块一律丢弃不展示。

10. **Trace日志落库**
    每一轮完整记录：用户原始query、LLM思考内容、tool_call入参、工具返回结果、是否成功；存入本地SQLite，用于调试Agent行为。
    前端用户提问入库前截到 1000 字（`clipStoredPrompt`），助手正文 8000 字、思考 2000 字。
